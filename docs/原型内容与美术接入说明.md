# 原型内容与美术接入说明

## 当前交付

读取技术方案与完整实施计划后，增加一个“先验证玩法和可替换内容”的独立批次。保留原 Demo，在 `src/` 迁入现有循环，新增三叶草金币命名、美术入口和事件工坊。不将本批次标记为 M1 或 M2 完成；Vite / TypeScript、正式存档、原生平台与发布验收继续沿用原计划。

## 美术替换

把图片放到 `src/assets/`，在 `src/assets.js` 的 `ASSETS` 填写本地相对路径，未配置（null）时继续使用 Demo SVG。支持 PNG、WebP、SVG、JPG，文件名建议英文、数字或连字符。重新执行 `npm run build`；资源不存在时构建会报错。独立 HTML 会内嵌这些图片，可连同单个文件离线交付。

| 字段 | 作用 | 当前占位尺寸与建议 |
| --- | --- | --- |
| background | 风景底图，覆盖天空、山坡、树木和地面；房屋与可点击物品仍在前景 | 横屏 1440×900、竖屏布局 760×1280；当前共用一张图居中裁切，最终构图到位后可增加横竖两张 |
| character | 场景和旅行插画里的角色 | 120×120 透明画布，保留边距；当前为单张静态图，动作精灵后续扩展 |
| clover | 每株三叶草，成熟与幼苗复用、缩放展示 | 建议透明 128×128；当前共用图，若要独立生长帧后续扩展 |
| currency | 余额、价格中的金币图标 | 建议透明 64×64，显示为 24×24 |
| items.rice / sandwich / cake / map / cup | 商店和行囊里的道具插图 | 透明 120×120 画布，居中显示 |

例如把 `character` 改为 `./assets/xiaoman.webp`，即可替换角色而不改游戏规则。正式素材提交后可由开发继续接入，并按新构图调整点击区域。房屋、背包、摊位等场景物品仍是现有 SVG 分层，不能把包含全部交互物品的整幅新画直接作为底图替换并假设点击位置一致；需要按素材分层和 `sceneLayout()` 一起对齐。美术来源与授权随正式资源补充。

## 自定义事件接口

玩家入口：设置 → 事件工坊。可直接编辑 JSON，导入文件先进入编辑区，点击“保存事件”才写入浏览器。导出的是当前编辑区中校验通过的 JSON。填入示例也需再次保存。重置游戏进度保留事件配置；要恢复示例，在工坊填入示例并保存。

```json
[
  {
    "id": "hill-new-friend",
    "title": "山坡上的新朋友",
    "text": "小满帮小松鼠找到了回家的路，收到几枚三叶草金币。",
    "theme": "hill",
    "tool": "map",
    "weight": 10,
    "at": 0.5,
    "coins": 12
  }
]
```

| 字段 | 约束 |
| --- | --- |
| id | 稳定且唯一的小写字母开头 ID，可含数字和连字符，最长 64 字符 |
| title / text | 标题 1–60 字符、正文 1–500 字符，作为纯文本显示 |
| theme | any 不限、hill 山野、town 小镇、lake 湖畔 |
| tool | null 不限、map 折叠地图、cup 搪瓷小杯；必须本次装包携带 |
| weight | 1–100 整数，只在符合条件的候选事件间计算相对概率 |
| at | 0.1–0.9，表示在整趟旅行的多少进度后可见 |
| coins | 0–100 整数，拆信收藏时领取一次 |

最多 100 条，JSON 最多 100000 字符。空数组关闭新旅行事件；没有符合条件的事件时正常旅行，不强制抽取。未知字段、重复 ID 或错误数值会拒绝保存。当前每趟最多一条事件，仅支持文本、条件与金币奖励，分支选择、掉落新道具、事件配图和事件链后续再加字段与迁移。

开发接口：`validateEvents(value)` / `parseEvents(raw)` 验证配置；`depart(state, now, random, events)` 开始旅行；`planEvent(...)` 抽取并生成带 eventId 和 occurredAt 的快照。出发后结果写入游戏状态，编辑事件或刷新页面不会重抽；途中事件只展示，归来拆信时结算金币，重复领取不重复发奖。已领取历史最多保留 100 条，界面展示最近 10 条。

事件配置保存成功后才替换内存中的定义；写入失败会提示未保存。配置与游戏进度分开存储，可导出事件配置备份。此原型继承 Demo 的 localStorage 存档，尚未实现技术方案中的串行事务、备份恢复及跨端存档导入导出。
